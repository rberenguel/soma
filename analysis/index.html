Soma Cube Solution Analysis

Ruben Berenguel, 2025

This tool analyzes the 240 unique solutions to the Soma Cube by grouping them into structural classes and mapping the relationships between them. The process is broken down into three main steps, each with its own interactive visualization.

How It Works

Step 1: Compute Graph Classes

First, the tool identifies all 240 solutions and groups them into unique structural classes based on their piece-adjacency graphs. This initial step is required as it generates the data needed for the other visualizations. For a detailed explanation of how these classes are calculated, see the expandable section below the controls.

Step 2: Compute Meta-Graph

This visualization generates a "meta-graph" showing how the solution classes are interconnected. An edge between two classes means you can transform a solution from one class into a solution from the other through a simple 2- or 3-piece move.

Step 3: Compute Full Solution Graph

This generates the full solution graph, also known as the SOMAP (Soma Map), explored before by Richard Guy, John H. Conway, and Donald Knuth. Initially, the graph displays placeholders for all 240 canonical solutions.

As you find solutions using my Soma cube simulator, you can load them here, and they will populate the graph. This allows you to see which solutions you've found and use the graph's connections to guide you toward discovering the remaining ones. You can toggle between viewing connections made by 2-piece moves only, or by both 2- and 3-piece moves. If you're interested, you can see a rendering of Knuth's original SOMAP-3 graph here.

How are graph classes calculated?

To find the unique structural class for each graph, we compute a canonical label. This is a unique string that represents the graph's structure, regardless of how its pieces (vertices) are named.

Two solutions belong to the same class if their graphs are isomorphic—meaning they are structurally identical.

Our method is a brute-force approach suitable for small graphs:

  • We generate all 7! (5,040) possible permutations of the piece labels ('A' through 'G').
  • For each permutation, we create a new, relabeled version of the graph.
  • We then convert this relabeled graph into a unique string:
    • First, the graph's nodes (pieces) are sorted alphabetically (A, B, C...).
    • We iterate through the sorted nodes, building the string. For each node, we append its name, a colon, its alphabetically-sorted neighbors, and a semicolon.
    • This creates a segment like A:BCF; for a single node. The final string is a concatenation of all segments, e.g., A:BCF;B:ADG;....
  • The lexicographically smallest string found across all 5,040 permutations is chosen as the graph's official canonical label.

All isomorphic graphs will produce the exact same canonical label, allowing us to group them together.
