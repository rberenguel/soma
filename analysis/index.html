Soma Cube Solution Analysis

Ruben Berenguel, 2025

The same solver used in the simulator to assign a unique identifier to solutions, finds all 240 unique solutions, which are then grouped into unique structural classes based on their piece-adjacency graphs. You can find more details in the summary box below. You need to run this first, since it generates data structures needed for the other two.

The meta-graph is a state graph of 2 or 3 piece moves that can transform some solution in the class to another solution in another class. This graph is fully connected, and will open in its own tab, since it is pretty large. The node SVG images are those generated in the previous step, and downloaded.

The full solution graph is also known as the SOMAP (see Knuth). This will generate the full connection graph of canonical solutions, and how to move across them with changes of 2 or 3 piece moves. It will open in its own tab.

It will show no solutions, but just placeholders. If you find solutions using my Soma cube simulator, you can load them and they will show in the graph. Then you can use the graph to guide you in finding the missing solutions.

You can optionally disable the 3-piece option to see only 2 piece changes. The 2/3 version (sometimes referenced as SOMAP-3) has two connected components: one with 239 solutions, and one with one solution. The 2 version (SOMAP-2) is disconnected, and has several singletons. If you are curious to see Knuths's SOMAP-3 graph, I added a renderer for it here.

How are graph classes calculated?

To find the unique structural class for each graph, we compute a canonical label. This is a unique string that represents the graph's structure, regardless of how its pieces (vertices) are named.

Two solutions belong to the same class if their graphs are isomorphic—meaning they are structurally identical.

Our method is a brute-force approach suitable for small graphs:

  • We generate all 7! (5,040) possible permutations of the piece labels ('A' through 'G').
  • For each permutation, we create a new, relabeled version of the graph.
  • We then convert this relabeled graph into a unique string:
    • First, the graph's nodes (pieces) are sorted alphabetically (A, B, C...).
    • We iterate through the sorted nodes, building the string. For each node, we append its name, a colon, its alphabetically-sorted neighbors, and a semicolon.
    • This creates a segment like A:BCF; for a single node. The final string is a concatenation of all segments, e.g., A:BCF;B:ADG;....
  • The lexicographically smallest string found across all 5,040 permutations is chosen as the graph's official canonical label.

All isomorphic graphs will produce the exact same canonical label, allowing us to group them together.
